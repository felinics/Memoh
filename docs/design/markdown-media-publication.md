# Markdown 媒体发布

模型通过正文引用图片 `![说明](/data/image.png)` 和文件 `[文件名](/data/report.pdf)`。远程 HTTP(S) 图片可以引用；普通网页链接和带行号的源码链接不会自动上传。行内代码、代码块和未闭合的 Markdown 不触发文件读取。

`send` 工具保留，但不再向模型暴露顶层或 `message.attachments`。chat 模式通过正常回复发布当前会话内容；向其他会话发送时必须指定平台和目标，并在平台解析目标别名后再次拒绝当前会话。discuss 模式仍由 `send` 决定是否发言。schedule 保留显式发送能力。

## 发布与展示

- `internal/markdownmedia` 使用 Goldmark 解析引用及原文范围，归档文件，生成资产绑定。此逻辑不在 Agent runtime 内。
- chat 消息持久化时保留原始正文，在现有 metadata 和 message assets 中记录绑定；不新增数据库字段。UI 投影将引用替换为经过鉴权的媒体地址。
- IM 在公共 Channel 出站层将引用展开为有序的正文、图片和文件，随后使用各平台既有的格式化、分段和附件上传实现。最终回复优先使用该 run 已持久化的资产绑定，不重新读取可能改变的源文件。
- 流式输出暂存可能的引用，最终消息才发布媒体。同一 stream 重试最终事件时跳过已经确认发出的片段。底层平台请求失败时是否接受了消息仍受平台 API 的语义限制。
- 不支持图片展示但支持附件的平台降级为文件；不支持附件的平台显示失败提示。Email 当前没有附件出站模型，正文里的媒体引用明确降级并报告部分成功。
- 部分媒体不可用时继续展示或投递其余内容。显式发送工具返回 `partial=true`；Email 返回 `status=partial`，避免模型把整条消息重发。

归档读取限定在 `/data` 内，使用 bridge 的 descriptor-anchored nofollow 读取，符号链接不会跟随。远程图片下载限制非公网地址、重定向和下载时长，并沿用媒体服务的大小限制。图片校验实际 MIME；底层存储诊断不进入用户正文。

## 自动化验证

覆盖引用语法及 UTF-8 范围、引用式链接、代码块排除、文件覆盖和删除后的历史快照、失败隔离、跨 Bot 读取隔离、非公网 URL、当前目标别名拦截、部分成功的 RPC 传递、流式引用及重复最终事件、Web 历史投影与鉴权 URL、Email 降级。

已运行公共出站测试和 `internal/channel/...` 下的适配器测试。平台名称参数化的公共出站测试不等于各平台真实 API 或 GUI 验收。

## 尚未完成的 Computer Use 验收

仅在已确认的专用测试会话操作，不向社区公共频道发送测试消息。

| 环境 | 必测行为 | 当前状态 |
| --- | --- | --- |
| Web | 正常回复直接显示图片；文件可下载；流结束后显示；刷新、覆盖和删除源文件后旧消息仍可用 | 待验证：本地 Docker/后端无响应，浏览器自动化操作也出现超时 |
| Discord | chat 单图、多图、图文顺序、文件下载、失败隔离；discuss 显式发送；验证没有重复消息 | 待验证：已查看客户端，未找到可确认用途的专用测试频道，需要测试目标 |
| Telegram | 同上，并检查媒体发送、caption/长文本分段、文件名及下载内容 | 待验证：客户端可截图，但坐标点击持续返回 `AXError.noValue`；需要确认测试 Bot/群 |

每个平台需记录测试 Bot、会话、运行版本、消息链接或 ID、截图，以及下载文件与原始 fixture 的哈希。自动化和 agent 操作不能替代 human QA。此文档不表示验收已经通过。
