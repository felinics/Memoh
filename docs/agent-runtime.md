# Agent Runtime

> Moved from `AGENTS.md` to keep the always-on project rules under the context injection limit. `AGENTS.md` links here where this material is needed.

## Agent Development

- The AI agent runs **in-process** within the Go server — there is no separate agent gateway service.
- `internal/agent/` is a bounded-package namespace. It intentionally contains no root Go package.
- `internal/agent/application/` owns turn orchestration: message assembly, history, memory, compaction, decisions, persistence, and runtime dispatch.
- The Twilight AI native runtime lives in `internal/agent/runtime/native/`; `agent.go` there provides `Stream()` (SSE streaming) and `Generate()` (non-streaming) methods.
- `internal/agent/turn/` is the pure port used by Channel and by the authenticated in-process/gRPC transports. Internal code says Thread; compatibility adapters keep external `session_id` and existing gRPC fields stable.
- Model/client types are defined in `internal/models/types.go`: `openai-completions`, `openai-responses`, `anthropic-messages`, `google-generative-ai`, `openai-codex`, `github-copilot`, `edge-speech`.
- Model types: `chat`, `embedding`, `speech`.
- Tools are implemented as `ToolProvider` instances in `internal/agent/tool/`, loaded via setter injection to avoid FX dependency cycles.
- **Tool usage lives with the tool, never in the static prompt.** Per-tool usage goes in `sdk.Tool.Description`; cross-tool workflow guidance goes in an optional `tools.ToolUsage` `Usage()` method that `assembleTools` injects only when that provider registers tools for the session. Because both are gated with the tool itself, the prompt template never names conditionally-registered tools (guarded by `internal/agent/runtime/native/prompt_test.go`) and can't drift — the cause of the original `speak` / `search_memory` / `schedule` bugs.
- Prompt templates are embedded from `internal/agent/runtime/native/prompts/`. Partials (reusable fragments) are prefixed with `_` (e.g., `_memory.md`, `_identities.md`). System prompting combines `system_common.md` with mode-specific prompts such as `mode_chat.md` and `mode_discuss.md`.
- Internal chat state lives under `internal/chat/`: `thread` owns Thread lifecycle/forks, `message` owns persistence, `timeline` owns canonical event projection, and `view` owns API/UI history projection. These packages do not orchestrate Agent execution.
- The chat timeline (`internal/chat/timeline/`) owns canonical events, projection, rendering, persistence, and context composition. Inbound adaptation lives in `internal/channel/inbound/`, while discuss-mode driving lives in `internal/channel/discuss/`.
- Browser Use and Computer Use capabilities live in `internal/agent/tool/browser.go` (plus `internal/agent/tool/computer_a11y.go`) and are exposed only when the bot's workspace display is enabled. `browser_action` / `browser_observe` operate the headed workspace Chrome/Chromium instance over CDP, `browser_remote_session` exposes the same CDP endpoint for code-driven Playwright/CDP sessions, and the Computer Use pair (`computer_observe` / `computer_action`) drives the broader GUI desktop: snapshots come from the AT-SPI accessibility tree via the bundled `a11y-cli` Rust helper at `/opt/memoh/toolkit/display/bin/a11y-cli`, and raw RFB pointer/keyboard input remains as a fallback when accessibility cannot reach the target. Both browser and computer screenshots are saved to a workspace path; with `image_mode: auto` (the default) they are also handed to the model on its next step when the model accepts images and shown in the conversation (see the observation notes below), otherwise the model must read the path explicitly. Prefer Browser Use for web pages; use Computer Use for native dialogs, non-browser apps, or GUI states that CDP cannot reach.
- Browser Use / Computer Use calls are validated against a per-tool action contract (`internal/agent/tool/gui_contract.go`, with the definitions in `browser_contract.go` and `computer_contract.go`) before anything touches the browser or desktop. One spec per action drives the generated tool schema (the `action`/`observe` enum, including the compatibility aliases `dblclick`, `scrollintoview`, and `keyboard_inserttext`), the per-action reference text the model reads, and the pre-execution checks: parameters that do not belong to the chosen action, unknown enum values, out-of-range numbers, conflicting locators (`ref` + `selector`, an element plus `x`/`y`, half a coordinate pair), `timeout` together with `duration_ms`, and `double_click` with a conflicting `click_count` are all rejected with no side effect. `timeout` is only a readiness bound (navigate/reload/history/wait-for-element, default 30 s, failures are returned instead of swallowed); `duration_ms` is the fixed pause for `wait` without a target. `fill` accepts an empty string to clear a field on both tools; the Computer fallback path clears with Select All + BackSpace before typing.
- The `a11y-cli` helper and `internal/agent/tool/computer_a11y.go` share a versioned JSON contract (`PROTOCOL_VERSION` in `crates/a11y-cli/src/main.rs`, `a11yProtocolVersion` in Go). Snapshot output carries `protocol_version`, `helper_version`, `limit`, `truncated`, `lines` (array), per-item `x/y/width/height` and interesting `states`, plus walk diagnostics (counters are returned to the model; the bus address stays in server logs). Output from any other protocol version, or a helper that rejects the `locate` subcommand or `--limit`, is reported as an outdated workspace image instead of being decoded into an empty tree. `a11y-cli locate --ref eN` resolves a ref from the persisted index without re-walking the tree, which is how double/triple clicks and middle/right buttons on a ref are replayed as real pointer events (AT-SPI's default action fires once and has no button). Elements whose box is missing or unrealised (GTK tree cells report extents near `i32::MIN`) never become pointer targets; such refs return an explicit error for pointer-only actions.
- Target identity (`internal/agent/tool/gui_session.go`, `gui_browsers.go`, `computer_context.go`): `computer_context` discovers and selects targets. `list_apps` / `get_app` enumerate applications on the AT-SPI bus (`a11y-cli apps`, `app_id` = `app:<pid>`, resolved through the bus daemon) and `list_browsers` / `get_browser` enumerate Chromium instances that expose a `--remote-debugging-port` (`browser_id` = `chrome-<port>`, the workspace browser is `chrome-9222` and the only one started on demand); `tab_id` is the CDP target id. Every browser call accepts `browser_id` / `tab_id` (or the compatibility `tab_index`) and every desktop call accepts `app_id`; when omitted, the per-session default set by `get_app`, `get_browser`, `tab_new`, `tab_select`, or the first page action is used. Defaults live in memory per (bot, session) and never leak across threads. `get_app` with `launch=true` starts an installed application (desktop entry, PATH lookup, or absolute path) as quoted argv and is classified as an `exec` operation by the tool approval policy (`approval.OperationForCall`), so exec policies govern it. `documentation` returns the contracts that generate the schemas plus per-backend capabilities.
- Refs are bound to snapshots. Browser observations pin the listed elements on the page under a `snapshot_id` (`memohTakeSnapshot`); a ref is resolved through that pinned list and refused when the page holds a different snapshot, the element was removed, or the document was navigated (`navigate`, `reload`, history also drop the session's record). Desktop snapshots carry a `snapshot_id` written into the helper's ref index; ref actions pass `--snapshot`, and the helper refuses refs taken in another snapshot. Desktop ref actions require a snapshot in the current session that covered the addressed application (a whole-desktop snapshot covers every application).
- Input actions beyond click/type: `set_value` (native value setter + input/change on the web; EditableText contents or Value-interface numbers on the desktop), `paste` (web: a real `paste` event carrying text/plain and, for `format=html`, text/html, with insertHTML / insertText fallbacks; desktop: xclip-backed clipboard, previous clipboard saved and restored unless it changed meanwhile, serialised per bot), `select_text` (unique `prefix+text+suffix` match; selects or places the caret before/after; UTF-16 offsets on the web, character offsets on the desktop), `secondary_action` (desktop: AT-SPI actions listed as `actions=` in the snapshot; browser: explicitly unsupported), `scroll` by `pages` of the target's visible area, and `keydown` / `keyup` that track held keys per session so later events carry their modifiers.
- Observation (`internal/agent/tool/browser_ax.go`, `gui_snapshot.go`, `computer_observe.go`): browser snapshots come from `Accessibility.getFullAXTree` (roles, computed names, values, states such as checked/disabled/expanded/focused, heading levels, hierarchy), joined to the interactive DOM elements by backend node id so every interactive node carries a ref and viewport bounds; password fields show `value="•••"`. When the accessibility domain is unavailable the listing degrades to the flat DOM scan and says `source: dom`. Desktop snapshots (`a11y-cli snapshot`, protocol 4) carry depth (indentation), `value` for editable text and Value-interface controls, states, and `actions=`. On both backends refs are stable across observations of the same target (backend node id on the web, bus name + object path on the desktop, via `--reuse`), so a second snapshot is **incremental** by default: only added (`+`), updated (`~`), and removed refs are listed, with `full_because` explaining any full listing (first observation, target or scope change, `disable_diffing`). `limit` sizes a page and `next_cursor` continues the most recent observation of the target (`cursor`), bounded by a byte budget; `scope_ref` re-observes one subtree; `truncated_reason` says why a listing stopped. Baselines are kept per target *and* scope, so a subtree observation diffs against the previous observation of that subtree and never replaces the whole-target baseline. Refs outside an observed subtree keep their ids: the browser assigns refs page-wide whatever the scope, and the desktop helper carries the unobserved entries of the previous index over (`carried`, reported as `carried_refs`) so the next whole-target snapshot reuses them; carried refs still resolve for accessibility actions but are never pointer targets until observed again. Baselines and pages live in the per-session GUI state and are dropped on navigation or tab close.
- Screenshots (`gui_screenshot.go`, `media_output.go`): every capture reports pixel size and its coordinate space (viewport CSS pixels with device pixel ratio and scroll offset for the browser, document coordinates for `full_page`, desktop pixels with scale 1 for the desktop). `image_mode: auto` (default) also hands the image to the model on its next step through the same decoration path as `read` (`MediaToolOutput`, `decorateReadMediaTools` wraps `browser_observe` and `computer_observe`) when the model accepts images, and shows it in the conversation as an attachment; otherwise, or with `image_mode: path`, the result says `image_delivery: path_only` and why. `state_and_screenshot` takes both in one call with timestamps and a `consistent` flag (document generation on the web, application set on the desktop); `probe` reports what each backend can do right now without private diagnostics.
- Headless Playwright scripts are still ordinary workspace commands, but they are not the same path as the headed workspace browser/display stack. Use the headed Browser Use tools when the user needs to inspect or operate the visible workspace browser.
- The compaction service (`internal/agent/context/compaction/`) handles LLM-based conversation summarization.
- Loop detection (text and tool loops) is built into the agent with configurable thresholds.
- Tag extraction system processes inline tags in streaming output (attachments, reactions, speech/TTS).
